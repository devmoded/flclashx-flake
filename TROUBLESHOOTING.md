# Решение проблем

Здесь собраны проблемы, которые не связаны с самим flake'ем: настройки
приложения, поведение ядра, особенности сети. Если установка ещё не
проверена, начните с [README](README.md).

## TUN-интерфейс есть, но трафик идёт напрямую и IP не меняется

### Симптомы

- `ip link` показывает устройство `FlClashX` (или имя из
  `tunMode.interfaceName`), `systemctl status flclashx-helper` — `active`,
  процесс `FlClashCore` запущен.
- При этом внешний IP не меняется, часть сайтов не открывается, а явных
  ошибок в интерфейсе нет.
- В журнале helper'а видны строки вида

  ```
  [TCP] dial GLOBAL <source> --> <target> error: dial tcp <ip>:<port>: i/o timeout
  ```

  Обратите внимание: `--> <target>` — это всегда запрошенный сайт. Признак
  `DIRECT` — когда и в ошибке (`dial tcp <ip>`) указан адрес конечного сайта,
  а не сервера подписки.

### Причина

В режиме **«Глобальный» (Global)** mihomo отправляет весь трафик через
встроенный селектор `GLOBAL`. Пока в `GLOBAL` ничего явно не выбрано, он
указывает на `DIRECT` (первый элемент своего списка). Выбор узла внутри
группы подписки на этот режим не влияет: группа участвует только в режиме
«Правила» (или когда она выбрана внутри `GLOBAL`).

В итоге соединения идут напрямую. Ресурсы, заблокированные провайдером,
при этом не открываются, хотя сам TUN и ядро работают штатно.

### Как проверить

При запущенном приложении запросите состояние группы `GLOBAL` у ядра
(порт и секрет берутся из `config.yaml`; ниже — значения по умолчанию):

```bash
config="$HOME/.local/share/com.follow.clashx/config.yaml"
secret=$(awk '/^secret:/{print $2}' "$config")
curl -s -H "Authorization: Bearer $secret" http://127.0.0.1:9090/proxies/GLOBAL \
  | grep -o '"now":"[^"]*"'
```

`"now":"DIRECT"` подтверждает, что трафик идёт мимо прокси. Если в
`external-controller` указан другой адрес или порт, подставьте его.

Косвенная проверка по журналу:

```bash
journalctl -u flclashx-helper -f
```

- `--> <target>` — это всегда запрошенный сайт, поэтому по нему режим не
  определить;
- если в тексте ошибки `dial tcp <addr>` стоит адрес конечного сайта, значит
  использовался `DIRECT`;
- если там адрес сервера подписки (или ошибка про рукопожатие/протокол узла),
  значит трафик шёл через узел.

### Решение

1. Переключите режим на **«Правила» (Rule)** — начнут работать правила
   профиля и выбранный в группе подписки узел.
2. Либо останьтесь в «Глобальном», откройте раздел «Прокси» → группу
   `GLOBAL` и выберите в ней группу подписки или конкретный узел.
3. Проверьте результат:

   ```bash
   curl -sS -m 8 https://api.ipify.org; echo
   ```

   IP должен смениться на адрес узла.

### Что не поможет

Смена стека TUN (`gvisor`, `system`, `mixed`, `mips`) не влияет на выбор
исходящего соединения. Стек определяет, как ядро обрабатывает пакеты, а не
через какой узел они уходят.

### Почему встроенная проверка IP может врать

Некоторые сервисы проверки IP (например, `ip-api.com`) могут быть
недоступны у провайдера и без VPN. Если такой запрос завершается таймаутом,
это не обязательно означает, что прокси не работает — проверьте на другом
сервисе.
